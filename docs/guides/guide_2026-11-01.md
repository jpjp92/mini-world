# 미니 월드 개발 가이드

> 마지막 업데이트: 2026-11-01 · 기획 상세는 [plan_2026-11-01.md](../plans/plan_2026-11-01.md)

## 1. 시작하기

```bash
pnpm install
cp .env.example .env.local   # 값 채우기 (아래 4장)
pnpm dev                     # http://localhost:3000
```

- 패키지 매니저는 **pnpm만** 써요. `npm install`은 `package-lock.json`을 만들어 `pnpm-lock.yaml`과 꼬여요.
- Node.js 24 기준.

## 2. 명령어

| 명령 | 하는 일 |
|------|------|
| `pnpm dev` | 개발 서버 (Turbopack) |
| `pnpm build` | 프로덕션 빌드 |
| `pnpm start` | 빌드 결과 실행 |
| `pnpm lint` | ESLint |
| `pnpm typecheck` | 라우트 타입 생성 + `tsc --noEmit` |
| `pnpm test` | Vitest 단위 테스트 (`tests/unit`) |
| `pnpm test:e2e` | Playwright E2E (`tests/e2e`, 빌드 후 3100 포트로 실행). `pnpm dev` 실행 중이면 빌드가 멈출 수 있어요 → dev를 끄거나 `pnpm build && pnpm start -p 3100`을 먼저 띄우고 실행. 3100에 예전 서버가 남아 있으면 화면이 안 떠요(`ss -ltnp \| grep 3100`으로 확인 후 종료) |
| `pnpm test:legacy` | v23 원본 기준 테스트 (로컬 전용, `ref/2d_v23.html` 필요) |
| `python3 scripts/extract_v23.py .` | v23 원본 → `src/legacy/v23/` 다시 생성 (로컬 전용) |
| `pnpm add <pkg>` / `pnpm add -D <pkg>` | 패키지 추가 |
| `pnpm exec playwright install chromium` | Playwright 브라우저 설치 (처음 한 번) |

## 3. 프로젝트 구조

```
mini-world/
  src/
    app/          # Next.js App Router. `/` = 게임(v23 레거시), `/lab` = 새 엔진 실험
    ui/           # LegacyRoot → LegacyGame(v23 부팅), GameRoot → GameCanvas(새 엔진)
    legacy/v23/   # v23 원본에서 생성한 game.js·markup.ts·v23.css (이름만 변경)
    engine/       # rAF 루프, 입력, 그리기 헬퍼. React·Next 의존 금지
    world/        # 월드 요소 (캐릭터, 이후 섬·NPC·장식)
    games/        # (Phase 2) 종목 모듈 11개
    store/        # gameStore(Zustand), saveData(기본값·검사·직렬화, 저장 v4)
    config/       # roster, world 등 밸런스·데이터 상수
  tests/unit/  tests/e2e/
  docs/
    plans/        # 기획 plan_YYYY-MM-DD.md
    logs/         # 작업 일지 log_YYYY-MM-DD.md
    guides/       # 개발 가이드 guide_YYYY-MM-DD.md
```

### 레거시 모듈 방식 (Phase 1)
- v23 스크립트를 이름만 바꿔 `src/legacy/v23/game.js`로 넣고, `/`에서 그대로 실행해요. 화면·밸런스가 v23과 같아요.
- 기능을 하나씩 `src/engine`, `src/world`, `src/games`, `src/store`로 떼어내고, 레거시 쪽 코드는 지워요. 레거시 파일이 비면 Phase 2 완료.
- 저장 키: `mini-world-save`. 첫 실행 때 옛 v23 저장을 복사하고 캐릭터 id를 바꿔요 (`src/config/legacy.ts`).
- `src/legacy/`는 ESLint 대상에서 빼요.
- **상태 연결**: 레거시 코드는 `state` 객체를 직접 바꿔요. `gameStore`는 같은 객체를 들고 있고, `dirty()`·불러오기·새로 시작 때 `rev`를 올려요. React UI는 `rev`를 구독해 다시 그려요.
- **저장 형식 v4**: v2/v3과 필드는 같고 버전 표시만 4예요. 불러오기 검사는 `src/store/saveData.ts`의 `sanitizeSave` 하나에서 해요.

### 설계 원칙
- **엔진과 React 분리**: 매 프레임 루프는 React 밖에서 돌고, React는 메뉴·모달·HUD만 그려요.
- **`src/engine`, `src/games`는 Next.js를 import하지 않아요** (프레임워크 독립).
- **상태 두 층**: 저장되는 `state`(코인·레벨·기록)는 store, 저장 안 되는 `runtime`(입력·카메라·진행 중 판)은 엔진 내부.
- **밸런스 값은 `src/config/`에만.** 이전 중에는 v23 숫자를 바꾸지 않아요.
- **캐릭터 이미지**: 저장소에 넣지 않고 `NEXT_PUBLIC_CHARACTER_BASE_URL`에서 `<id>.webp`로 불러와요. 없으면 도형 캐릭터.

| 변수 | 단계 | 공개 여부 |
|------|------|------|

- 로컬: `.env.local` (또는 `.env`). 둘 다 git 제외.
- Vercel: Project Settings → Environment Variables (Production·Preview). `SUPABASE_SECRET_KEY`는 Sensitive로 저장.

## 4-1. 배포 (Vercel)

- 프로덕션: https://mini-world26.vercel.app
- `main`에 push하면 자동 배포, 다른 브랜치·PR은 미리보기 배포.
- 빌드 설정은 기본값(Next.js, pnpm 자동 감지). E2E는 Vercel에서 돌리지 않아요 — push 전에 로컬에서 확인.
- 롤백: Vercel 대시보드 → Instant Rollback.

## 5. Supabase

- 다른 게임과 같이 쓰는 공유 프로젝트. 미니 월드 객체는 **`mini_world` 스키마**와 **`mini-world-characters` 버킷**에만 만들어요.
- 테이블: `profiles`, `saves`, `runs` + 뷰 `leaderboard_weekly`. 전부 RLS.
- 클라이언트 접근: `supabase.schema('mini_world')`. 대시보드 Settings → Data API → Exposed schemas에 `mini_world`가 있어야 해요.
- 마이그레이션 SQL과 검토 쿼리는 저장소에 넣지 않고 로컬(`supabase/migrations/`, `supabase/review.sql`)에 보관해요.
- 캐릭터 이미지: `mini-world-characters` 버킷에 `<id>.webp` 12장. 새 id 이름(`atti`, `kicko`, `curvy` 등)으로 올려요. 원본은 로컬 `public/characters/`(gitignore).

## 6. 저장소 규칙

- 공개 저장소예요. 커밋 금지: `ref/`(v23 원본), `public/characters/`, `supabase/`, `.env*`.
- 원작·실제 구단 이름(미니언, 바르샤 등)은 `src/`에 넣지 않아요. `tests/unit/no-legacy-names.test.ts`가 검사해요.
- 커밋 메시지는 한국어로 써요 (`feat:`, `docs:` 같은 접두사는 OK). push는 직접 해요.

## 7. 문서 규칙
