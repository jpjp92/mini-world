# 미니언 월드 웹 전환 기획 (2026-10-31)

> 최초 기획안이에요. v23 코드와 대조해 다시 정리한 최신본은 [plan_2026-11-01.md](plan_2026-11-01.md)를 보세요.

---

## 1. 목표와 범위

지금 미니언 월드는 약 1MB짜리 HTML 파일 하나(v23)에 이미지, 폰트, 약 3,000줄의 JS가 모두 들어 있어요. 이 구조로는 기능을 나눠 개발하기 어렵고, 저장도 브라우저 한 곳(localStorage)에만 남아요. 그래서 `jpjp92/mini-world` 저장소에 Next.js 앱으로 옮겨서 Vercel로 배포하고, 이후 Supabase로 계정과 기록을 서버에 저장하려고 해요.

### 1차 범위 (MVP)
- v23의 게임 플레이, 화면, 밸런스를 그대로 옮겨요. 세 섬, 11종목, 레벨/챔피언, 장식, 퀘스트가 대상이에요.
- Vercel 배포와 PR마다 미리보기 URL을 붙여요.
- 저장은 우선 localStorage를 유지하고, 지금의 저장 포맷(version 4)과 호환되게 해요.

### 2차 범위
- Supabase 로그인(익명, 이메일/소셜)으로 기기 간 이어하기를 지원해요.
- 종목별 리더보드와 주간 기록을 넣어요.

### 이번에 하지 않는 것
- 실시간 멀티플레이, 결제, 네이티브 앱, 게임 로직 재설계는 다루지 않아요. 옮기는 동안에는 규칙을 바꾸지 않아요.

## 2. 기술 스택

| 영역 | 선택 | 이유 |
|------|------|------|
| 프레임워크 | Next.js (App Router) + React + TypeScript | Vercel과 궁합이 좋고, 메뉴/모달 같은 UI를 컴포넌트로 나눌 수 있어요. 게임 값(저장 포맷, 점수)을 타입으로 잡을 수 있어요. |
| 게임 렌더링 | 기존 Canvas 2D 코드 유지 | 지금 코드가 이미 Canvas 2D라서 Phaser/Pixi 같은 엔진으로 다시 짜지 않아도 돼요. |
| UI 상태 | Zustand | 게임 루프와 React UI가 같은 상태를 보기 쉽고, 렌더링 없이도 읽고 쓸 수 있어요. |
| 스타일 | 기존 CSS를 CSS Modules로 옮김 | 지금 디자인을 그대로 유지하기 가장 쉬워요. Tailwind는 나중에 새 화면부터 선택적으로 써요. |
| DB / 인증 | Supabase (Postgres, Auth, RLS) | 익명 로그인을 지원하고, 행 단위 권한(RLS)으로 내 저장만 읽고 쓸 수 있어요. |
| 배포 | Vercel | GitHub 연동 자동 배포, PR 미리보기, 환경 변수 관리가 쉬워요. |
| 테스트 | Vitest + Playwright | 저장/점수 로직은 단위 테스트, 지금 쓰는 봇/회귀 테스트는 Playwright로 그대로 옮겨 CI에서 돌려요. |
| 패키지 관리 | pnpm | 빠르고 Vercel에서 기본 지원해요. |

## 3. 아키텍처

핵심 원칙은 **게임 엔진과 React를 분리**하는 것이에요. 매 프레임 돌아가는 캔버스 루프(`requestAnimationFrame`)는 React 렌더링 밖에서 돌고, React는 메뉴, 모달, HUD 같은 UI만 그려요. 이렇게 하면 매 프레임 리렌더가 없어서 지금 성능을 유지할 수 있어요.

- 게임 페이지는 `'use client'` 컴포넌트에서 `<canvas>` 두 개(월드, 아케이드)를 만들고, `useEffect`에서 엔진을 시작/정리해요. SSR에서는 엔진을 불러오지 않아요(`dynamic(..., { ssr: false })`).
- 상태는 두 층으로 나눠요.
  - `state`(저장되는 것: 코인, 레벨, 기록)는 Zustand 스토어
  - `runtime`(저장 안 되는 것: 입력, 카메라, 진행 중인 게임)은 엔진 내부 객체
- 종목은 공통 인터페이스(`init`, `update(dt)`, `draw(ctx)`, `onAction`)로 나눠서 파일 하나에 하나씩 두어요. 지금처럼 `a.id==='figure'` 분기가 여기저기 흩어져 있는 구조를 풀어요.
- 밸런스 값(목표 점수, 템포, 코스트)은 `config/` 아래 한 곳에 모아요.

### 폴더 구조 (안)

```
mini-world/
  app/
    layout.tsx            # 폰트, 메타
    page.tsx              # 게임 진입 (클라이언트)
    leaderboard/page.tsx  # 2차
    api/                  # 2차: 점수 검증 등
  src/
    engine/               # 루프, 입력, 카메라, 사운드, 그리기 공통
    world/                # 섬, 지역, 스테이션, NPC, 장식
    games/                # soccer.ts, figure.ts, taekwondo.ts ... (11개)
    ui/                   # Header, Sidebar, Modal, ArcadeHud, Settings ...
    store/                # Zustand: state, save/load, 마이그레이션
    config/               # games.ts, islands.ts, roster.ts, balance.ts
    lib/supabase/         # 클라이언트, 타입 (2차)
  public/
    characters/  fonts/  sprites/
  tests/
    unit/  e2e/           # Vitest, Playwright 봇
```

## 4. 저장과 데이터 (Supabase)

로그인 없이도 바로 플레이할 수 있게, 처음에는 익명 로그인으로 시작하고 나중에 이메일이나 소셜 계정을 연결하면 같은 저장이 유지되게 해요.

### 저장 흐름
1. 지금처럼 localStorage에 먼저 저장해요(오프라인에서도 동작).
2. 로그인 상태면 몇 초 단위로 묶어서(debounce) Supabase에도 올려요.
3. 접속 시 서버와 로컬 중 `updated_at`이 최신인 쪽을 쓰고, 충돌하면 두 저장을 보여주고 고르게 해요.
4. 기존 v23 사용자의 localStorage 저장은 첫 로그인 때 서버로 가져와요.

### 테이블 (안)

| 테이블 | 주요 컬럼 | 용도 |
|------|------|------|
| `profiles` | id(auth.users), nickname, char, created_at | 닉네임, 대표 캐릭터 |
| `saves` | user_id, version, data jsonb, updated_at | 지금 저장 포맷을 그대로 JSON으로 (1인 1행) |
| `runs` | user_id, game_id, level, champ, score, duration, created_at | 게임 한 판 기록 (리더보드, 통계) |
| `leaderboard` (view) | game_id, level, champ, best_score, nickname | 종목별 주간/전체 순위 |

### 권한과 보안
- 모든 테이블에 RLS를 켜서 `auth.uid() = user_id`인 행만 읽고 쓸 수 있게 해요. 리더보드 뷰만 모두에게 읽기 가능해요.
- 점수는 클라이언트에서 조작할 수 있어요. 리더보드를 열 때는 서버(Route Handler 또는 Edge Function)에서 종목별 최대 점수, 판 길이(25초 안팎) 같은 기본 검증을 넣어요.
- Supabase 키는 Vercel 환경 변수로만 넣고, service role 키는 서버에서만 써요.

## 5. 에셋과 성능

- **이미지**: HTML 안의 base64 캐릭터 사진(현재 WebP)을 `public/characters/*.webp` 파일로 빼요. 캔버스에서 쓰는 이미지는 시작 시 미리 불러오고(로딩 화면), UI용은 `next/image`를 써요.
- **폰트**: base64로 넣은 폰트는 `next/font/local`로 옮겨 서브셋과 캐시를 적용해요.
- **코드 분할**: 11개 종목 코드를 동적 import로 나눠 처음 로드를 줄여요.
- **목표**: 첫 화면 JS 200KB 이하(gzip), 모바일(iPhone 13 에뮬레이션) 60fps 유지. 지금 쓰는 프레임 측정 스크립트(p50/p95)를 CI에 넣어 회귀를 막아요.
- **오프라인/앱 느낌 (선택)**: PWA 매니페스트를 넣어 홈 화면에 추가할 수 있게 해요.

## 6. 단계별 로드맵

| 단계 | 할 일 | 완료 기준 |
|------|------|------|
| Phase 0 · 준비 | Next.js + TS 프로젝트 생성, ESLint/Prettier, pnpm, Vercel 연결, v23을 `public/legacy.html`로 올려 바로 플레이 가능하게 | Vercel URL에서 v23이 그대로 돌아감 |
| Phase 1 · 그대로 옮기기 | 에셋 분리, 엔진/월드/UI 모듈화, 헤더·사이드바·모달을 React로, 저장은 localStorage 그대로 | Playwright 회귀 22종목 + 저장 테스트 통과, v23 저장 파일 그대로 불러옴 |
| Phase 2 · 종목 분리 | 11개 종목을 `games/*.ts`로, 밸런스 값을 `config/`로, 봇 밸런스 테스트를 CI로 | 종목별 봇 점수가 v23과 동일 범위 |
| Phase 3 · Supabase | 익명 로그인, profiles/saves 테이블, RLS, 클라우드 저장 + 로컬 저장 가져오기 | 두 기기에서 같은 저장 이어하기 |
| Phase 4 · 기록과 순위 | runs 기록, 리더보드 페이지, 점수 기본 검증, 계정 연결(이메일/소셜) | 종목별 주간 순위 노출 |

Phase 0은 하루 안에 끝낼 수 있고, 바로 배포된 게임을 확인할 수 있어서 추천하는 첫 단계예요. 가장 큰 작업은 Phase 1이에요.

## 7. 리스크와 결정할 것

### 리스크
- **캐릭터 이미지 권리**: 미니언은 일루미네이션/유니버설의 캐릭터예요. 공개 저장소와 공개 URL로 배포하면 저작권/상표 문제가 생길 수 있어요. 개인 학습용이면 저장소를 private로 두거나 Vercel 배포에 비밀번호 보호를 걸고, 공개할 거라면 오리지널 캐릭터로 바꾸는 걸 추천해요.
- **옮기는 동안의 회귀**: 3,000줄을 나누다 보면 미세한 동작이 바뀔 수 있어요. 지금 회귀/봇 테스트를 먼저 CI에 올리고 옮기는 것이 안전해요.
- **점수 조작**: 클라이언트 게임이라 완벽한 방지는 어려워요. 리더보드는 기본 검증 + 신고/숨기기 수준으로 시작해요.
- **Supabase 무료 플랜**: 일주일 미사용 시 프로젝트가 일시 중지될 수 있어요. 로컬 저장을 먼저 쓰는 구조라 게임은 계속 돌아가요.

### 결정할 것
- [ ] 저장소와 배포를 공개로 할지, 비공개(또는 비밀번호 보호)로 할지
- [ ] 스타일: 기존 CSS 유지(추천) vs Tailwind로 재작성
- [ ] 로그인 방식: 익명 시작 + 나중에 연결(추천) vs 처음부터 소셜 로그인
- [ ] 캐릭터 특전(perk) 코드: 다시 켜기 vs 옮기면서 삭제 (리뷰 문서의 미답 질문)
- [ ] Phase 0부터 제가 바로 저장소에 올릴지 (저장소 접근 연결이 필요해요)
